Jask propose sept types d’objets pour configurer l’IA, automatiser un processus ou guider un utilisateur. Cette page vous aide à choisir celui qui correspond à votre besoin.

## Comparer les concepts

| Si vous voulez… | Utilisez… |
| --- | --- |
| Définir des instructions réutilisables | Un **prompt** |
| Répondre à des demandes dans une interface conversationnelle | Un **agent** |
| Automatiser une suite d’actions | Un **agent** ou **workflow** |
| Faire intervenir plusieurs agents dans une réflexion | Un **groupe d’agents** |
| Ajouter une action ou un traitement spécialisé | Un **skill** |
| Guider l’utilisateur dans un scénario interactif | Une **expérience** |
| Choisir le moteur d’IA utilisé | Un **modèle** |

## Comprendre chaque concept

### Prompt

Un **prompt** est un ensemble d’instructions réutilisables transmis à un modèle d’IA. Il peut définir le comportement d’un agent ou être exécuté dans un workflow.

Pour un agent d’analyse financière, un prompt peut préciser :

- son rôle, comme celui d’un analyste financier senior ;
- le format attendu, comme un tableau ou une synthèse structurée ;
- les limites à respecter, comme l’absence de recommandations d’investissement ;
- le ton et les règles applicables aux réponses.

<Tip>
  Testez le prompt avec plusieurs demandes représentatives. Ajustez-le si les réponses varient trop en structure, en ton ou en niveau de détail.
</Tip>

### Agent

Un [agent](/docs/catalog/agents) répond aux demandes d’un utilisateur dans une interface conversationnelle.

Il génère ses réponses avec un modèle d’IA. Il peut aussi utiliser des bases de connaissances et appeler des outils selon la demande reçue.

Ces outils peuvent, par exemple, générer un graphique ou une image, appeler une base de données ou une API personnalisée.

**Choisissez un agent** lorsque l’utilisateur doit poser des questions, préciser son besoin et recevoir une réponse adaptée au contexte.

### Workflow

Un [workflow](/docs/catalog/agents/applications) automatise un processus défini. Il peut exécuter des prompts, appeler des agents et déclencher une série d’actions préconfigurées.

Par exemple, un workflow peut exploiter des services liés à Microsoft, traduire du contenu ou lancer une recherche approfondie.

<Warning>
  Dans certaines pages ou interfaces, les workflows peuvent encore être appelés **applications**, **Agent Workflows** ou **mini-apps**. La terminologie peut donc varier.
</Warning>

**Choisissez un workflow** lorsque les actions doivent suivre un enchaînement prévisible, notamment pour automatiser une tâche répétitive.

### Groupe d’agents

Un [groupe d’agents](/docs/catalog/agents/group) rassemble plusieurs agents spécialisés.

Selon sa configuration, le groupe peut :

- orchestrer plusieurs agents pour atteindre un objectif ;
- sélectionner l’agent le plus pertinent pour une demande ;
- interroger plusieurs agents simultanément.

**Choisissez un groupe d’agents** lorsque plusieurs expertises sont nécessaires pour traiter une même demande.

### Skill

Un [skill](/docs/catalog/skills), ou **capacité**, définit une action ou un traitement spécialisé réutilisable par plusieurs agents.

Un skill peut, par exemple :

- produire un rapport selon le format attendu par un comité exécutif ;
- mettre en forme des données financières ;
- générer un fichier ;
- analyser un document selon une structure définie ;
- interagir avec un outil externe.

Contrairement à un modèle, qui génère du contenu, un skill ajoute une logique d’action ou un format de traitement spécifique.

**Choisissez un skill** lorsque plusieurs agents doivent appliquer la même méthode, produire le même format ou exécuter la même action.

### Expérience

Une [expérience](/docs/catalog/experiences) est un scénario interactif qui guide l’utilisateur dans une tâche précise.

Elle pose les questions nécessaires, puis orchestre les appels aux agents ou aux workflows concernés. Une expérience peut enchaîner plusieurs cas d’usage sans exposer l’orchestration sous-jacente à l’utilisateur.

**Choisissez une expérience** lorsque l’utilisateur doit être accompagné étape par étape dans un parcours interactif.

### Modèle

Un [modèle LLM](/docs/catalog/ai_models) est le moteur d’IA qui analyse les instructions et génère les réponses.

Les administrateurs de Jask déploient les modèles disponibles dans la plateforme. Ces modèles peuvent notamment être fournis par OpenAI, Mistral, Anthropic ou xAI.

Tous les modèles du marché ne sont donc pas nécessairement proposés dans votre environnement Jask.

**Choisissez un modèle** pour déterminer le moteur utilisé par un agent ou un autre objet compatible.

## Distinguer les concepts proches

### Agent ou workflow ?

Choisissez un **agent** lorsque l’utilisateur échange avec l’IA et que la réponse dépend de sa demande. L'agent garde de la liberté sur l'exécution des tâches qu'il doit réaliser, et la manière de parvenir à son but, bien que le prompt puisse lui donner un maximum de consignes.

Choisissez un **workflow** lorsqu’une suite d’actions doit être exécutée selon un processus défini.

### Workflow ou expérience ?

Un **workflow** automatise les actions sous-jacentes.

Une **expérience** organise l’interaction avec l’utilisateur et peut appeler des workflows ou des agents pendant le parcours.

### Agent ou groupe d’agents ?

Un **agent** fournit une expertise ou un comportement principal.

Un **groupe d’agents** combine plusieurs agents lorsque la demande nécessite plusieurs expertises ou une sélection automatique de l’interlocuteur.

### Prompt ou skill ?

Un **prompt** définit les instructions transmises au modèle.

Un **skill** définit une action, une méthode de traitement ou un format réutilisable.
